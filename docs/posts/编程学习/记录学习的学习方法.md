## 目录结构建议（Obsidian）

笔记库/  
├── 00-模板/              ← 本目录，放本文里的 8 个模板  
├── 10-卡点本/            ← 一坑一文件，文件名 = 报错关键词  
├── 20-代码片段库/         ← 一场景一文件，文件名 = "场景：做什么事"  
├── 30-概念卡/            ← 一概念一文件  
├── 40-项目/              ← 一项目一文件夹，必含 README.md  
├── 50-日志/              ← 每日记录 + 每周复盘  
└── 90-归档/              ← 只读不做的旧笔记，全扔这里

**命名规则（决定你三个月后能不能搜到）**：

- 卡点本：`踩坑-Spring-事务不回滚.md` —— 文件名放**关键词**，不要放"第几章"
    
- 代码片段：`场景-Java-读取Excel并去重.md` —— 放**场景**，不放技术名
    
- 概念卡：`什么时候该用线程池.md` —— 放**问题**，不放定义
    

> 为什么强调这个：你忘了定义可以查；忘了"什么时候该用它"，你连查什么都不知道。 记"什么时候用"的笔记才救得了你，记"它是什么"的笔记不会。

# 一张图记住：什么该记，什么不该记

| 内容                   | 记不记     | 放哪        |
| -------------------- | ------- | --------- |
| 我报错了，花了 40 分钟才修好     | ✅ 必记    | 卡点本       |
| 一段跑通的、以后还会用的代码       | ✅ 必记    | 代码片段库     |
| 这个概念"什么时候该用、什么时候不该用" | ✅ 记     | 概念卡       |
| 项目的启动步骤和踩坑           | ✅ 必记    | 项目 README |
| 老师 PPT 上的知识点整理       | ❌ 不记    | —         |
| 课程大纲 / 目录            | ❌ 不记    | —         |
| API 参数清单             | ❌ 不记    | 查官方文档     |
| 概念的标准定义              | ❌ 抄了也没用 | 忘了再查      |
# 给 AI 的三句话（配合这些模板用）

1. 别给我答案，先问我三个问题帮我定位卡在哪一步

2. 我这段代码的思路是什么？错在第几步？只说这一步，不要重写整段

3. 就这个知识点出五道题考我，我答完你再批改。  
   要求：只考"会不会用"，不要考"记不记得定义"

> **AI 是考官、评审、挖坑者，不是代写。** 20 分钟规则：卡住先自己折腾 20 分钟，再问 AI；问之前先写下"我的预期 / 实际结果 / 我的猜测"。
