- AI 智能伴侣功能实现
	- 项目介绍
		- 基于大模型的情感陪伴应用
		- 用户设定昵称与性格
		- AI 以对应人设对话
	- 环境准备
		- 前端 Nginx
			- 解压目录无中文无空格
			- 双击 `nginx.exe` 启动
			- 占用 88 端口
			- 端口在 `conf/nginx.conf`配置文件下
			- 停止
				- 终端停止命令：`nginx.exe -s stop`
				- 任务管理器结束进程
			- 不会开机自启
		- 服务端 FastAPI
			- 新建 `ai_partner` 项目
				- 选 FastAPI 模板自动装依赖
				- 自动生成实例与样例代码
				- 拷入 `data` 目录
			- 给app对象配置
				- `title` 
				- `description` 
				- `version`
			- `uvicorn.run` 启动
	- 前后端交互流程
		- 访问 `:88` 返回 `index.html`
		- 页面加载后请求 `/api/presets`
		- nginx 把 `/api` 转发到 `:8000`
		- 服务端处理经 nginx 回前端
		- 前端看 `:88`，后端单测接口看 `:8000`
	- 接口一：预设加载
		- `GET /api/presets`
		- 数据源 `data/companion_presets.json`
			- 判断文件是否存在: if not os.path.exists("data/companion_presets.json")
			- 创建相应结果对象
				- code
				- message
				- data
		- 文件不存在返回 500
		- 先 Swagger 自测再联调
	- 接口二：新建会话
		- 定义接收创建会话参数的类
			- 接收前端数据
				- nick_name
				- nature
		- `POST /api/sessions`
		- 请求体 `nick_name` / `nature`
		- 会话名 = 时间戳 `%Y-%m-%d_%H-%M-%S`
		- 一个会话一个 json
			- session_name
			- nick_name
			- nature
			- messages
	- 新学的代码知识
		- 新建文件: os.mkdir(文件名)
		- 获取当前时间: datetime.now().strftime("%Y-%m-%d_%H-%M-%S")
			- 结果返回的是字符串
		- <mark style="background:#d3f8b6">字段名和相应内容必须与前端 json 对齐</mark>
	- 接口三：与 AI 交互
		- `POST /api/chat`
		- 请求体 4 字段
			- session_name
			- message
			- `nick_name`
			- nature
		- 创建接收chat请求参数类
		- 系统提示词模板
			- 规则内容
			- 性格占位 `%s`
			- 使用的时候在名字后加%然后填写占位缺少的内容
		- 消息滚雪球
			- system提示词每次根据请求参数重建
			- 历史 messages 全量拼入
			- 追加本轮 user输入
		- 调模型
			- `stream=False`
			- `reasoning_effort=high`
			- `thinking` 关闭
		- 回写文件
			- 追加 AI的assistant 内容回复
			- 覆盖角色 nick_name / nature
			- 整份保存 `json.dump`
	- 坑与易错点
		- Nginx 没启动
		- 请求参数和响应参数和前端不对称
	- 代码思路梳理总结
		- 抽象问题具体化
		- 比如列表里的很长的对象要看成单个列表元素
		- 方法都是通用的
		- 修改数据之前一定都是先查询数据
		- CURD的时候都要判断东西是否存在, 存在之后再执行
