- AI 应用实战功能实现
	- [ ] 审视：对照笔记逐节核对，确认讲义丢失的两张表（约束、SQL 分类）没有漏点
	- 会话管理
		- 会话列表
			- `GET /api/sessions`
			- `os.listdir` 取文件名
			- 只留 `.json`
			- 去后缀 `[:-5]`
			- 倒序排 `reverse=True`
		- 加载指定会话
			- `GET /api/sessions/{session_name}`
			- 不存在返回 404
			- 存在返回完整 json
		- 删除会话
			- `DELETE /api/sessions/{session_name}`
			- `os.remove` 删文件
	- RESTful 规范
		- GET 查询
		- POST 新增
		- PUT 修改
		- DELETE 删除
		- 资源名用复数
		- 是风格不是规定
	- 日志记录
		- `import logging`
		- `basicConfig` 配级别与格式
		- 级别 DEBUG < INFO < WARNING < ERROR < FATAL
		- 常规用 INFO，异常用 ERROR
		- 关业务日志：`level=FATAL`
		- 关访问日志：`access_log=False`
	- 全局异常处理
		- `@app.exception_handler(Exception)`
		- 参数 `request: Request`
		- `request.url` / `method` / `headers` / `client`
		- 返回 `JSONResponse`
		- 比每个接口 try/except 省事
	- 为什么换成数据库
		- 并发冲突
		- 查询统计慢
		- 数据维护难
		- 数据不安全
		- 扩展受限
	- MySQL 概述
		- 数据库 DB
		- 数据库管理系统 DBMS
		- SQL 结构化查询语言
		- 社区版 8.0.34
		- 常见库：Oracle / MySQL / SQL Server / PostgreSQL / SQLite
	- 数据模型
		- 关系型 = 二维表
		- 非关系型如 Redis
		- 服务器 → 库 → 表 → 行
	- SQL 与 DDL
		- 四类：DDL / DML / DQL / DCL
		- 库操作
			- `show databases`
			- `select database()`
			- `create database`
			- `use 库名`
			- `drop database`
			- `database` 与 `schema` 同义
		- 建表
			- `create table 表名(...)`
			- 字段 类型 约束 comment
			- 最后一列不加逗号
		- 约束
			- `primary key` 主键
			- `not null` 非空
			- `unique` 唯一
			- `default` 默认值
			- `foreign key` 外键
		- 主键自增
			- `auto_increment`
			- 从 1 开始
			- 删除后不回收编号
	- 图形化工具 DataGrip
		- 新建数据源选 MySQL
		- 端口默认 3306
		- 下载驱动需联网
		- 测试连接
		- 自带系统库不要删
	- 坑与易错点
		- json 不能直接写 Pydantic 对象
		- 中文乱码查字符集与 encoding
		- 路径参数别叫 `id`
		- `basicConfig` 只生效一次
