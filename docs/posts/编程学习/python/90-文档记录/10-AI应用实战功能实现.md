## RESTful 开发规范

前后端交互按 REST 风格设计接口。REST（`REpresentational State Transfer`，表述性状态转换）是一种**软件架构风格**，不是硬性规定。

| 动作 | 方法 | 示例 |
| --- | --- | --- |
| 查询 | `GET` | `GET /users/1`、`GET /users` |
| 新增 | `POST` | `POST /users` |
| 修改 | `PUT` | `PUT /users` |
| 删除 | `DELETE` | `DELETE /users/1` |

- 资源名用**复数**表示一类资源：`users`、`emps`、`books`
- <span style="color:#d83931">风格是约定不是规定</span>，可以打破；但团队内最好统一

## 完整代码

```python
import json
import os
from datetime import datetime
from typing import Any
from fastapi import FastAPI
from pydantic import BaseModel, Field
from openai import OpenAI

app = FastAPI(title="AI智能伴侣", version="1.0.0")

client = OpenAI(
    api_key=os.environ.get('DEEPSEEK_API_KEY'),
    base_url="https://api.deepseek.com")

SESSIONS_DIR = "sessions"
PRESETS_FILE_PATH = "data/companion_presets.json"
if not os.path.exists(SESSIONS_DIR):
    os.mkdir(SESSIONS_DIR)

def get_session_path(session_name: str) -> str:
    return os.path.join(SESSIONS_DIR, f"{session_name}.json")

class ApiResponse(BaseModel):
    code: int = 200
    message: str = "操作成功"
    data: Any | None = None

class CreateSessionRequest(BaseModel):
    nick_name: str
    nature: str

class ChatRequest(BaseModel):
    session_name: str
    message: str
    nick_name: str
    nature: str

# ========== 预设 ==========
@app.get("/api/presets", summary="获取预设伴侣信息列表", response_model=ApiResponse)
def presets():
    if not os.path.exists(PRESETS_FILE_PATH):
        return ApiResponse(code=500, message="预设文件不存在")
    with open(PRESETS_FILE_PATH, "r", encoding="utf-8") as f:
        presets_list = json.load(f)
    presets_list.sort(key=lambda x: x["sort_order"])   # 按序号排
    return ApiResponse(code=200, message="获取预设伴侣信息成功", data=presets_list)

# ========== 新建会话 ==========
@app.post("/api/sessions", summary="创建新会话", response_model=ApiResponse)
def create_session(request: CreateSessionRequest):
    session_name = datetime.now().strftime("%Y-%m-%d_%H-%M-%S")
    session_data = {
        "nick_name": request.nick_name,
        "nature": request.nature,
        "session_name": session_name,
        "messages": []
    }
    with open(get_session_path(session_name), "w", encoding="utf-8") as f:
        json.dump(session_data, f, ensure_ascii=False, indent=2)
    return ApiResponse(code=200, message="创建会话成功", data=session_name)

# ========== 对话 ==========
@app.post("/api/chat", summary="与AI交互", response_model=ApiResponse)
def chat(request: ChatRequest):
    with open(get_session_path(request.session_name), "r", encoding="utf-8") as f:
        session_data = json.load(f)

    messages = [{"role": "system", "content": SYSTEM_PROMPT_TEMPLATE % (request.nick_name, request.nature)}]
    for msg in session_data["messages"]:
        messages.append(msg)
    messages.append({"role": "user", "content": request.message})

    response = client.chat.completions.create(
        model="deepseek-v4-pro",
        messages=messages,
        stream=False
    )
    ai_response = response.choices[0].message.content

    messages.pop(0)                                    # 丢掉 system，system 不落盘
    messages.append({"role": "assistant", "content": ai_response})
    session_data["messages"] = messages
    session_data["nature"] = request.nature
    session_data["nick_name"] = request.nick_name

    with open(get_session_path(request.session_name), "w", encoding="utf-8") as f:
        json.dump(session_data, f, ensure_ascii=False, indent=2)
    return ApiResponse(code=200, message="请求成功", data=ai_response)

# ========== 会话列表 ==========
@app.get("/api/sessions", summary="获取会话列表", response_model=ApiResponse)
def list_sessions():
    session_list = []
    if os.path.exists(SESSIONS_DIR):
        for filename in os.listdir(SESSIONS_DIR):
            if filename.endswith(".json"):
                session_list.append(filename[:-5])
    session_list.sort(reverse=True)                    # 时间倒序
    return ApiResponse(code=200, message="获取会话列表成功", data=session_list)

# ========== 加载指定会话 ==========
@app.get("/api/sessions/{session_name}", summary="获取指定会话信息", response_model=ApiResponse)
def get_session_message(session_name: str):
    session_path = get_session_path(session_name)
    if not os.path.exists(session_path):
        return ApiResponse(code=404, message="会话不存在")
    with open(session_path, "r", encoding="utf-8") as f:
        session_data = json.load(f)
    return ApiResponse(code=200, message="获取会话信息成功", data=session_data)

# ========== 删除会话 ==========
@app.delete("/api/sessions/{session_name}", summary="删除指定会话", response_model=ApiResponse)
def delete_session(session_name: str):
    session_path = get_session_path(session_name)
    if not os.path.exists(session_path):
        return ApiResponse(code=404, message="会话不存在")
    os.remove(session_path)
    return ApiResponse(code=200, message="删除会话成功")

if __name__ == '__main__':
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

> `SYSTEM_PROMPT_TEMPLATE` 沿用昨天那 8 条规则 + 性格占位，这里省略；完整版见 `09-AI智能伴侣功能实现.md`。

## 日志记录

用 `logging` 替代到处 `print`，三步：

```python
import logging

# ① 基础配置：级别 + 格式
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s - %(levelname)s - [%(filename)s:%(lineno)d] - %(message)s"
)

# ② 记日志
logging.info("访问首页~")
logging.error("某个错误")
```

- **日志级别**（由低到高）：`DEBUG` → `INFO` → `WARNING` → `ERROR` → `FATAL`
- `level=logging.INFO` 表示「只输出 INFO 及以上」，DEBUG 会被吞掉
- 常规流程用 `INFO`，错误/异常用 `ERROR`

**关日志的两种方式**

```python
logging.basicConfig(level=logging.FATAL)                    # 业务日志全关
uvicorn.run(app, host="0.0.0.0", port=8000, access_log=False)  # 关 uvicorn 访问日志
```

## 全局异常处理

两种做法：每个接口 `try...except`（繁琐、不推荐），或 FastAPI 的全局异常处理器（推荐）。

```python
from fastapi import Request
from fastapi.responses import JSONResponse

@app.exception_handler(Exception)
def handle_exception(request: Request, e: Exception):
    logging.error(f"处理异常, 请求路径: {request.url}, {request.method}, 异常信息: {e}")
    return JSONResponse(content={"code": 500, "message": "后端代码异常，请联系开发人员即时排查", "data": None})
```

![](./../50-归档/下载下来的飞书讲义/讲义导出/讲义/static/day10-Python-AI应用实战%28功能实现%29-cjnpknD8.png)

用 json 文件存会话，随用户量上来会碰到五个问题：

| 问题 | 说明 |
| --- | --- |
| 并发冲突 | 多人同时操作同一份文件会互相覆盖 |
| 查询统计慢 | 要统计、分析就得读所有文件再逐个处理 |
| 数据维护难 | 增删改都要整份读写 |
| 数据不安全 | 文件读写权限限制低 |
| 扩展受限 | 单机存储容量有限，扩容麻烦 |

## MySQL 概述

![](./../50-归档/下载下来的飞书讲义/讲义导出/讲义/static/day10-Python-AI应用实战%28功能实现%29-cyqd3nue.png)

- **数据库（DataBase, DB）**：存储和管理数据的仓库
- **数据库管理系统（DBMS）**：操作和管理数据库的大型软件
- **SQL（Structured Query Language）**：结构化查询语言，操作关系型数据库的统一标准

![](./../50-归档/下载下来的飞书讲义/讲义导出/讲义/static/day10-Python-AI应用实战%28功能实现%29-corE9ntg.png)

<span style="color:#d83931">程序员发 SQL 给 DBMS，DBMS 再去操作数据库里的数据</span>。

常见数据库：

| 数据库 | 特点 |
| --- | --- |
| Oracle | 大型收费，价格昂贵 |
| MySQL | 开源免费，Sun 收购后又被 Oracle 收购；有商业版和社区版 |
| SQL Server | 微软收费中型库，C#/.NET 常用 |
| PostgreSQL | 开源免费，占用率上升，很多大模型库支持 |
| DB2 | IBM 大型收费 |
| SQLite | 嵌入式微型库，Android 内置 |
| MariaDB | MySQL 的分支，兼容性好 |

**安装**：官网 `https://dev.mysql.com/downloads/mysql/`，课程用社区版 **8.0.34**（免费、无官方技术支持）。

## 数据模型

![](./../50-归档/下载下来的飞书讲义/讲义导出/讲义/static/day10-Python-AI应用实战%28功能实现%29-cMj5Anud.png)

**关系型数据库（RDBMS）**：建立在关系模型上、由多张相互连接的**二维表**组成的数据库。

二维表的优点：格式统一便于维护；SQL 操作标准统一，支持复杂查询。

> 基于二维表存数据 = 关系型；不是的（如 Redis）= 非关系型。

![](./../50-归档/下载下来的飞书讲义/讲义导出/讲义/static/day10-Python-AI应用实战%28功能实现%29-chBpznGQ.png)

层级关系：<span style="color:#d83931">数据库服务器 → 多个数据库 → 多张表 → 多行记录</span>。所以建数据要走三步：建库 → 建表 → 插数据。

## SQL 语句

SQL 按功能分四类：

| 分类 | 全称 | 作用 |
| --- | --- | --- |
| DDL | Data Definition Language | 定义数据库对象（库、表） |
| DML | Data Manipulation Language | 增删改表中的数据 |
| DQL | Data Query Language | 查询表中的数据 |
| DCL | Data Control Language | 定义访问权限、安全级别 |

### 数据库操作（DDL）

```sql
-- 查询所有数据库
show databases;

-- 查当前在哪个库
select database();

-- 创建（MySQL 8 默认字符集就是 utf8mb4）
create database [if not exists] 数据库名 [default charset utf8mb4];

-- 使用
use 数据库名;

-- 删除
drop database [if exists] 数据库名;
```

- 同一个服务器里不能有两个同名库，重复创建会报错，所以常用 `if not exists`
- 删除不存在的库会报错，所以常用 `if exists`
- `database` 可以换成同义的 `schema`：`create schema db01;`、`show schemas;`

### 表操作

```sql
create table 表名(
    字段1  字段1类型 [约束] [comment '字段1注释'],
    字段2  字段2类型 [约束] [comment '字段2注释'],
    ......
    字段n  字段n类型 [约束] [comment '字段n注释']
) [comment '表注释'];
```

- `[ ]` 里是可选项；<span style="color:#d83931">最后一个字段后面不能有逗号</span>
- 例：

```sql
create table tb_user (
    id int comment 'ID,唯一标识',
    username varchar(20) comment '用户名',
    name varchar(10) comment '姓名',
    age int comment '年龄',
    gender char(1) comment '性别'
) comment '用户表';
```

### 约束

**约束**：作用在表字段上的规则，用来限制存进表里的数据，保证数据的正确性、有效性、完整性。

| 约束 | 关键字 | 作用 |
| --- | --- | --- |
| 主键 | `primary key` | 唯一标识一行，非空且唯一 |
| 非空 | `not null` | 该字段不能为 NULL |
| 唯一 | `unique` | 该字段值不能重复 |
| 默认值 | `default` | 不传时用默认值 |
| 外键 | `foreign key` | 关联另一张表的主键 |

```sql
create table tb_user (
    id int primary key auto_increment comment 'ID,唯一标识',
    username varchar(20) not null unique comment '用户名',
    name varchar(10) not null comment '姓名',
    age int comment '年龄',
    gender char(1) default '男' comment '性别'
) comment '用户表';
```

### 主键自增

`auto_increment`：每次插入新行，数据库自动给主键生成值，从 1 开始递增。

- 只能用在主键上
- 删掉的数据不会让序号回退

## 坑与易错点

- **`json.dump` 不能直接 dump Pydantic 对象**，要先 `model_dump()`；会话数据是原生 dict，没这个问题
- **中文乱码**：建库时字符集不对、或读写文件漏了 `encoding="utf-8"`；MySQL 8 默认 `utf8mb4`，老版本要显式指定
- **`id` 自增不会因为删除而回收**：删了 id=3，下次插入还是 4
- **DELETE 接口路径参数别用 `id` 命名**：会盖住内置 `id()`，也跟接口文档的 `book_id` 之类对不上
- **`logging.basicConfig` 只生效一次**：重复调用不会覆盖已有配置，改级别要用 `logging.getLogger().setLevel(...)`
- 路径分隔符：Windows 上 `f"{dir}/{name}.json"` 也能用，但 `os.path.join` 更稳
