1、请叙述下，条件判断第三种格式完整的执行流程（if 条件1...elif 条件2... elif 条件3... else）

::: details 答案

`if-elif-else` 是多分支条件判断结构。程序会从上到下依次判断每个条件，一旦某个条件为 True，就执行该条件对应的代码块，执行完后直接跳出整个结构，后面的 `elif` 和 `else` 不再判断。如果所有 `if` 和 `elif` 条件都为 False，则执行 `else` 分支。

它的特点是顺序判断、短路执行，并且整个结构最多只会执行一个分支。

:::



2、请叙述下，while循环完整的执行流程 : 
``` python
变量定义   
while  条件 
	循环体
	量更新
```

::: details 答案

`while` 循环的执行流程是：先<span style="color:#d83931">定义并初始化</span>循环变量，然后判断 `while` 条件。如果条件为 True，就执行循环体；循环体执行完后执行变量更新，再回到条件判断处重新判断。直到当条件变为 False 时，退出循环，继续执行循环后面的代码。

它属于先判断后执行的循环，如果第一次条件就为 False，循环体一次也不会执行。实际使用时要注意变量更新，避免死循环。

:::


3、请说一下什么时候使用无限循环，如果需要结束无限循环了怎么办？可以举个例子

::: details 答案

无限循环一般用在循环次数事先不确定、需要持续监听、持续交互或者失败重试的场景，常见写法是 `while True`。它并不是没有退出条件，而是退出条件通常放在循环体内部判断。结束无限循环最常用的是 `break`

如果循环在函数里也可以用 `return`，程序需要整体退出可以用 `sys.exit()`，异常场景可以 `raise`。

比如做一个命令行菜单，用 `while True` 持续等待用户输入，当用户输入 `exit` 时执行 `break` 退出循环。实际开发中要注意保证有明确的退出路径，避免真正的死循环。

:::


4、分别说一下range(end),range(start,end)，range(start,end,step) 取值范围

::: details 答案


`range` 的取值范围遵循左闭右开原则。
`range(end)` 等价于 `range(0, end, 1)`，取值是 0 到 end-1；
`range(start, end)` 等价于 `range(start, end, 1)`，从 start 开始到 end-1 结束；
`range(start, end, step)` 从 start 开始，每次增加 step，直到不包含 end 为止。

如果 step 是正数，要求 start 小于 end；
如果 step 是负数，要求 start 大于 end；
step 不能为 0。
它返回的是 range 对象，是惰性序列，不是列表。

:::

3、请说一下什么是索引？容器索引的范围是多大？遍历容器的时候，想要同时获取元素的索引，使用哪个函数？

::: details 答案


索引就是元素的<span style="color:#d83931">位置编号</span>，从零开始数。

长度是 n 的序列，正向范围是 0 到 n-1
负索引从 -1 开始，-1 是最后一个

遍历容器的时候，想要同时获取元素的索引使用 <span style="color:#d83931">enumerate() 函数</span>

样例：
```
lst = ["苹果", "香蕉", "橙子"]

for i, x in enumerate(lst):
    print(i, x)

# 0 苹果
# 1 香蕉
# 2 橙子
```

1、请说出自定义模块中使用__all__ 有什么作用？ __init__模块中使用__all__有什么作用？

::: details 注意

- **自定义模块里的 `__all__`
-  `__all__ = ["名字1","名字2"]` 控制 `from 模块名 import *` 导入的时候
	- 只会导入列表里面写的变量、函数、类；不在列表里的不会被 `import *` 导入。
	- 注意：不影响明确写名字的导入（`import xxx` / `from xxx import yyy`）
- **包的 `__init__.py` 里面的 `__all__`
	-  控制 `from 包名 import *` 时，会导入 `__all__` 里面列出的**子模块名**。
	- 比如 `__all__ = ["test_mod"]`，执行 `from mypkg import *` 就等价于自动 `import mypkg.test_mod`

:::

2、什么是包？为什么要定义包？ 【from 包名   import \*】是什么意思? 【 from 包名.模块名 import   \*】又是什么意思？

::: details 注意

- 包就是一个**包含 `__init__.py` 文件的文件夹**，用来管理一堆相关的模块（.py文件）。
- Python3.3+支持隐式命名空间包，但学习阶段考试/面试默认：包=带`__init__.py`的文件夹
---
- 分类管理模块，避免模块名字冲突
- 层级清晰，方便维护大量代码
- 方便批量导入、组织项目结构
---
- `from 包名 import *` 导入这个包 `__init__.py` 中 `__all__` 列表里声明的**子模块**。 前提：包的`__init__.py`里写了`__all__`，否则默认不会导入任何子模块。
- `from 包名.模块名 import *` 导入**指定模块**中 `__all__` 里面列出的内容（函数、变量、类），和普通模块import *规则一致。

3、说一下，什么是类属性、什么是实例属性？有什么区别？什么时候将属性定义为类属性，什么时候定义为实例属性？

::: details 注意

- **类属性**：写在类里面、方法外面，属于**类本身**，所有实例共享这一份数据
- **实例属性**：一般在 `__init__` 里用 `self.xxx` 定义，**属于单个实例对象**，每个对象独立一份

✅ 区别

1. 归属：类属性归类；实例属性归实例
2. 共享：类属性所有对象共用；实例属性每个对象互不干扰
3. 修改：类属性通过类名修改，全部对象可见；实例属性只影响自己这个对象

✅ 使用时机

- **类属性**：所有实例都相同、不变/统一统计的值。比如：计数count、常量、统一配置
- **实例属性**：每个对象独有的数据。比如：每个人的姓名、年龄



:::

4、什么是魔法方法？请说出至少4个常见的魔法方法？并说出他们各自的运行的时机？

::: details 注意

魔法方法：以 `__开头、__结尾` 的特殊方法，**不需要手动调用，在特定时机由Python自动触发执行**。

常见4个：

1. `__init__`：构造方法。**创建实例对象之后自动执行**，用来初始化实例属性（给self绑定属性）
2. `__eq__`：**创建实例对象之前自动执行**，负责开辟内存、返回对象（先new，再init）
3. `__str__`：print(对象) 或者 str(对象) 的时候自动执行，要求返回字符串，用来给人看的描述
4. `__del__`：对象被销毁、垃圾回收的时候自动执行（程序结束/对象引用计数为0）

补充常考备选： `__repr__`：交互式控制台输出对象时触发； `__len__`：调用len(对象)自动触发，必须返回整数

## Day08

- [x] 1). 请描述一下 IP 地址、域名、端口号，这三部分的作用是什么？

::: details 答案

- **IP**：唯一定位互联网上的一台设备。IPv4 是 32 位二进制，日常写成四段十进制，每段 0~255，如 `132.12.86.125`；`127.0.0.1` 是<mark style="background:#d3f8b6">本机回环地址</mark>。
- **域名**：IP 不好记，所以用一串点分隔的英文代替，<mark style="background:#d3f8b6">通过 DNS 把域名解析成 IP</mark>。`localhost` 是<span style="color:#d83931">本机域名</span>，等同 `127.0.0.1`。
- **端口**：取值 0~65535，用来标识设备上运行的程序。HTTP 默认 80，HTTPS 默认 443。

:::



- [ ] 2). 什么是 HTTP 协议？请求数据和响应数据的格式各分为几个部分？

::: details 答案

- HTTP 是超文本传输协议，规定客户端与服务器之间数据传输的规则。
- 请求格式**三部分**：请求行、请求头、请求体。
  - 请求行 = 请求方式 + 资源路径 + 协议版本
  - 请求头从第二行开始，格式 `key: value`
  - 请求体和请求头之间有一个空行，用于标记请求头结束
- 响应格式**三部分**：响应行、响应头、响应体。
  - 响应行 = 协议及版本 + 状态码 + 状态码描述，如 `HTTP/1.1 200 OK`
- 常见状态码：200 请求成功、400 请求参数错误、404 资源不存在、500 服务器发生不可预期的错误。

:::


- [ ] 3). GET 和 POST 的区别是什么？哪些情况建议使用 POST？

::: details 答案

- **GET**：参数拼在请求行里，`?` 之后按 `key=value&key=value` 的格式传，没有请求体；参数长度受浏览器和服务器限制。
- **POST**：参数放在请求体里，协议层面没有大小限制，实际仍受服务器配置约束。
- 建议用 POST 的情况：提交账号密码等敏感数据、上传文件、参数多或含中文特殊字符、会修改服务器数据的操作。
- 一句话：只做查询用 GET，提交或修改数据用 POST。

:::


- [ ] 4). AI 大模型本身具备会话记忆能力吗？如果想让大模型具备会话记忆，通用做法是什么？

::: details 答案

- 不具备。DeepSeek 这类大模型的服务端不会记录用户请求的上下文，每次请求都是独立的。
- 通用做法是**上下文拼接**：每次请求把之前的对话历史一起放进 `messages` 列表发过去。
- `messages` 里每条消息按 `role` 分三类：`system` 设定人设、`user` 是用户提问、`assistant` 是模型回复。
- 缺点是上下文会无界膨胀、耗 Token，还受模型最大长度限制。
- 优化方案：滑动窗口只保留最近 N 轮、把早期对话压缩成摘要、用 RAG 只取相关的历史。

:::


- [ ] 5). 使用 FastAPI + uvicorn 定义一个能被前端访问的接口，需要哪些步骤？

::: details 答案

- 第一步装包：`uv add fastapi uvicorn`。FastAPI 是 Web 框架，uvicorn 是运行它的服务器。
- 第二步创建实例：`app = FastAPI()`。
- 第三步定义路由：用 `@app.get("/路径")` 或 `@app.post(...)` 装饰器把函数和访问路径绑定，函数里返回 dict 或 Pydantic 模型。
- 第四步启动：命令行 `uvicorn 模块名:app --reload`，或在代码里 `uvicorn.run(app, host="0.0.0.0", port=8000)`。
- host 写 `0.0.0.0` 是为了让本机以外的设备也能访问；启动后浏览器打开 `http://localhost:8000/路径` 就能拿到 JSON。

:::

- [ ] 1). 如果前端使用 POST 请求传递了参数 `{"name":"张三","age":23,"hobby":"打豆豆"}`，服务端如何接收该参数？

::: details 答案

- 定义一个 **Pydantic 模型**，继承 `BaseModel`，字段名和类型跟前端传的 JSON 一一对应。
- 把模型写在**路由函数的形参**上，FastAPI 看到这个类型就知道要从**请求体**里读 JSON。
- 读完会自动做类型校验和转换，再装成一个对象传进函数，函数里用 `user.name` 这样取值。
- 字段名对不上、或者少传字段，FastAPI 会返回 **422**，不是 500。
- 某个字段可有可无时给它设默认值，比如 `hobby: str | None = None`。
- 这种方式只适合 POST，GET 的参数要从请求行里取，不用模型。

```python
from pydantic import BaseModel

class User(BaseModel):
    name: str
    age: int
    hobby: str

@app.post("/user")
def add_user(user: User):        # 形参类型是模型，就从请求体收
    print(user.name, user.age, user.hobby)
    return ApiResponse(code=200, message="接收成功")
```

:::


- [ ] 2). 请描述一下，如果让你开发一个服务端接口，你一般怎么做？

::: details 答案

- **先看接口文档**：接口地址、请求方式、请求参数、响应示例，这四项不清楚就别动手写。
- **定义模型**：一个统一的响应模型 `ApiResponse`（`code`、`message`、`data`），一个请求体模型。
- **绑定路由**：用 `@app.get("/api/xxx")` 或 `@app.post(...)` 装饰器把路径和函数连起来。
- **写业务**：先判断数据源是否存在，不存在就返回 `code=500` 和提示信息；存在就读取、处理。
- **统一返回**：不管成功失败都返回 `code`、`message`、`data` 三件套，前端只认这一套结构。
- **先自测再联调**：先在 `http://localhost:8000/docs` 上把接口调通，再打开前端页面走完整流程。

:::


- [ ] 3). 使用目前学习的内容回答：前端发起请求后，服务端没收到，一般是什么问题？服务端收到了也返回了 200，但数据没渲染到页面，一般是什么问题？

::: details 答案

**服务端没收到**，按现在的部署方式查这四处：
- Nginx 没启动。它不会开机自启，每次关机重开都要手动双击 `nginx.exe`。
- 后端 8000 端口没启动，或者启动时报错退出了。
- `conf/nginx.conf` 里 `/api` 的转发规则没配对，请求没被转到 8000。
- 前端请求的地址或端口写错，请求压根没发到对的地方。

**服务端返回 200 但页面没数据**，重点看这几点：
- 把 **HTTP 状态码**和**业务 code** 搞混了。项目里文件不存在时返回的是 `ApiResponse(code=500, ...)`，这个响应的 HTTP 状态码仍然是 200，只是 `code` 字段是 500，前端如果只看 HTTP 状态就会以为成功。
- 响应结构和前端预期不一致。统一结构是 `{code, message, data}`，数据在 `data` 里，前端少取一层就是 `undefined`。
- 字段名对不上。预设列表里是 `nick_name`、`nature`、`sort_order`，前端按别的名字取就会是空。
- 前端 JS 报错卡住了，F12 的 Console 里会有红字。

:::


- [ ] 4). 前端页面部署在本机 Nginx（端口 88），浏览器访问 Nginx 是怎么获取到页面内容的？浏览器发起请求是直接请求到后端服务吗？请说一下完整的请求和响应链路。

::: details 答案

- 不是。浏览器所有请求都先到 88 端口的 Nginx，由 Nginx 再转发给后端，这叫反向代理。
- 第一步：浏览器请求 `http://localhost:88`，端口后没写具体资源，Nginx 默认返回 `index.html`。
- 第二步：浏览器解析 HTML、加载 CSS 和 JS，把页面渲染出来。
- 第三步：页面加载完，前端自动请求 `http://localhost:88/api/presets`，注意还是 88 端口。
- 第四步：`conf/nginx.conf` 里配了规则，`/api` 开头的请求转发给 `http://localhost:8000`。
- 第五步：FastAPI 处理完把结果响应给 Nginx，Nginx 再响应给浏览器，前端拿到数据渲染到页面。
- 两个入口别混：看完整项目走 `http://localhost:88/`，单独测接口走 `http://localhost:8000/docs`。

:::
